# ADR-009 — Les briques optionnelles ne sont jamais dans le chemin critique

- Statut : acceptée — 18 août 2026
- Source : P-10 (`cadrage/CAHIER-DES-CHARGES-FONCTIONNEL.md`, principes non négociables) ; RG-NF-01, RG-M02-01 ; contraintes C-02 et C-07 (`cadrage/STACK-TECHNIQUE.md` §1) ; STACK §4.2 et §4.6 ; `cadrage/PLAN-DE-REALISATION.md` §3.3

## Contexte

P-10 énonce **« dégradation, jamais panne »** : une brique optionnelle indisponible dégrade la fonctionnalité concernée avec un message clair, sans jamais empêcher l'usage du reste.

Deux briques sont désignées optionnelles par la pile technique, et elles sont exactement celles qui sont lentes et faillibles : le service local d'**embeddings** (Ollama, conteneur optionnel) et le **service Python de conversion** pour l'import bureautique (Pandoc, python-pptx, pdfplumber). C-02 exige de la recherche par sens une **bascule silencieuse en mots-clés** si elle est indisponible ; C-07 exige qu'un échec unitaire n'interrompe jamais un lot d'import.

La composition d'exploitation compte cinq services ; deux sont arrêtables sans erreur, et ce comportement est un critère de sortie du lot T-003.

## Décision

Les briques optionnelles ne sont **jamais dans le chemin critique**. Concrètement :

- Les vecteurs sont **conservés dans PostgreSQL avec pgvector** et fournis à l'index de recherche en mode `userProvided`. Service d'embeddings arrêté : l'index reste complet en mots-clés, le mode *Sens* se signale indisponible, l'hybride retombe sur les mots-clés — silencieusement pour l'utilisateur (RG-M02-01), avec une mention discrète prévue en `V-08`.
- Le calcul du vecteur est **différé** ; l'écriture dans l'index est synchrone à l'enregistrement. Une note est trouvable en mots-clés immédiatement, et par le sens quelques secondes plus tard.
- Le service de conversion est **isolé** et appelé fichier par fichier. Son arrêt dégrade l'import bureautique sans empêcher l'import Markdown, qui ne sort jamais de l'application.
- Les familles sémantiques et les autres travaux coûteux sont des tâches de fond `pg-boss`, adossées à PostgreSQL.

## Ce que cette décision interdit activement

- **Tout appel synchrone bloquant** vers le service d'embeddings ou vers le service de conversion depuis un chemin de rendu, d'enregistrement ou de recherche.
- **Toute attente du calcul d'un vecteur avant de déclarer une note enregistrée ou indexée.**
- **Tout écran, toute zone, toute route qui échoue** parce qu'une brique optionnelle est arrêtée. Une brique absente produit un état dégradé explicite, jamais une erreur, jamais un écran vide, jamais un chargement infini.
- **Toute dépendance du corps du produit à une brique optionnelle** : notes connexes et familles sémantiques se calculent en SQL sur les vecteurs déjà stockés, jamais par appel au service.
- **Toute interruption d'un lot d'import** par l'échec d'un fichier : un fichier en erreur est consigné, le lot continue.
- **Toute bascule bruyante** du mode *Sens* vers les mots-clés : la bascule est silencieuse pour l'utilisateur, avec la seule mention discrète prévue par la maquette.
- **Toute introduction d'un service supplémentaire dans le chemin critique**, y compris Redis : la file de tâches est dans PostgreSQL, une sauvegarde de la base sauvegarde l'état des traitements (C-13).

## Conséquences

- La base de vérité reste la base de vérité : l'index de recherche est reconstructible, les vecteurs sont en base.
- Chaque fonctionnalité adossée à une brique optionnelle doit posséder un **état dégradé maquetté** et un message clair ; l'absence d'un tel état est un vide de spécification à remonter, pas à combler.
- La composition d'exploitation doit démarrer et fonctionner avec les deux conteneurs optionnels arrêtés.
- Le mode simulation de l'import et le mode réel partagent le même chemin de code, donc la même tolérance aux échecs unitaires.

## Comment le vérifier

- **Batterie 14** — `pnpm test:degradation` : les deux conteneurs optionnels arrêtés, le produit reste pleinement utilisable et se signale dégradé. C'est la batterie nominale de cet ADR.
- **Batterie 9** — `pnpm test:etats` : l'état erreur d'une zone ne fait pas tomber la page.
- **Batterie 13** — `pnpm mesure:budgets` : un appel bloquant vers une brique optionnelle se voit dans les budgets.
- Critère de sortie du lot T-003 : `docker compose up`, les cinq services répondent, arrêt des deux optionnels sans erreur.
