## 2 · Ce qui rend ce lot sûr, et il faut le comprendre avant de coder

**La base a été semée DEPUIS `seeds/corpus.ts`** — `src/lib/base/semence.ts:47-66` importe `CORPUS` et
l'écrit en base. Les deux côtés portent donc **les mêmes données**.

Donc si ta couche de lecture rend **exactement** les formes de `seeds/corpus.ts`, les écrans afficheront
les mêmes pixels. **C'est vérifiable mécaniquement, et c'est ton critère de sortie principal.**

**Et le banc ne passe jamais par les routes** : il attaque les composants par le mode de conception,
qui continuera d'employer `corpusPourVue()`. Tu ne peux pas casser les 409 couples. **Ne les crains
pas ; prouve-les inchangés à la fin, c'est tout.**

## 3 · Ce que tu écris

### 3.1 · `src/lib/donnees/` — la couche de lecture

Une fonction par forme, rendant **le type déjà déclaré dans `seeds/corpus.ts`** — tu ne définis aucun
type nouveau, tu réemploies les siens :

| Forme | Type à rendre | Tables |
|---|---|---|
| les notes | `readonly Note[]` | `notes`, `etiquettesDeNote`, `etiquettes`, `verifications`, `typesDeNote`, `typesDeFiche` |
| les univers | `readonly Univers[]` | `univers`, `domaines` |
| les domaines et leurs modules | `readonly Domaine[]`, `readonly Module[]` | `domaines`, `modulesDeDomaine` |
| les relations | `readonly Relation[]` | `relations`, `typesDeRelation` |
| les comptes | `readonly Compte[]` | `comptes` |
| la configuration | `Configuration` | `parametres` |
| les templates, types de fiche, types de relation | leurs types | leurs tables |

**Passe par `basePartagee()` de `src/lib/base/acces.ts`.** N'ouvre aucune seconde connexion.

**Les dates.** `seeds/corpus.ts` porte des dates courtes françaises (`'18/07/2026'`) et un
`DATE_REFERENCE`. La base porte des `timestamptz` et des `date`. **La conversion est le point où l'on
se trompe** : rends exactement la même chaîne que le fichier, et prouve-le.

**La fraîcheur ne se recalcule pas ici.** `src/lib/fraicheur.ts` est l'implémentation unique (`P-01`).
Tu rends les dates ; le niveau vient de la fabrique.

### 3.4 · La batterie d'équivalence — **c'est le cœur de ce lot**

`pnpm verif:donnees` : **pour chaque forme, ce que la base rend est identique à ce que
`seeds/corpus.ts` exporte.** Comparaison profonde, sur les 32 notes, les 3 univers, les 4 domaines, les
19 dossiers, les relations, les comptes, la configuration.

**Et elle doit savoir dire non** : deux genres de mutation, code retour inversé, et **refus de conclure
si la mutation est inerte** — `verif/aller-retour.mjs --sonde=temoin-inerte` est le modèle, copie sa
forme.

**C'est cette batterie qui rend les huit lots suivants sûrs.** Sans elle, chacun devrait prouver sa
propre fidélité écran par écran.
