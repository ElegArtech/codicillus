# T-079 — La création d'une note, de bout en bout côté serveur

**Vague** : 1 · **Lot** : T-079 · **Ouvert le** : 21/08/2026
**Ferme** : le blocage de tête de `docs/reprise.md` — `/notes/nouvelle` rend **501**.

## 1. L'objet, en une phrase

`POST /notes/nouvelle` **écrit une note en base**, lui donne un identifiant lisible unique selon
`ARB-062`, l'entretient dans l'index, et **redirige en 303** vers `/notes/{identifiant}`.

## 2. Ce qui est arbitré, et qu'il ne faut donc plus demander

**`ARB-062` (`docs/arbitrages.md`) — À LIRE EN ENTIER AVANT D'ÉCRIRE.** La forme de l'identifiant
est tranchée : `n-` + `identifiantLisible(titre)` tronqué à 48 caractères sur frontière de tiret,
corps `note` si le slug est vide, collision levée par `-2`, `-3`, …, **unicité arbitrée par la
contrainte de base et non par une lecture préalable**, jamais recalculé après création.

**`ARB-063`** — le câblage du formulaire n'est PAS de ce lot. Il est écrit dans
`src/routes/notes/nouvelle/+page.svelte` par un autre lot. Tu écris l'action ; elle est atteinte
par un `POST` en `application/x-www-form-urlencoded`.

## 3. Le contrat de soumission — il est FIXE, ne l'invente pas

| champ | obligatoire | valeur |
|---|---|---|
| `titre` | oui | texte ; vide ou blanc ⇒ `fail(400, { motif: 'titre manquant' })` |
| `type` | oui | le **nom** d'un type de note (`types_de_note.nom`), tel que `#m-type` le rend |
| `domaine` | oui | le **nom** d'un domaine |
| `dossier` | oui | le chemin affiché, séparateur `SEPARATEUR_DE_CHEMIN` (` › `), relatif au domaine |
| `visibilite` | non | `interne` \| `publique` — défaut `interne` (défaut de colonne) |
| `statut` | non | `brouillon` \| `publiee` — défaut `brouillon` |
| `etiquettes` | non | noms séparés par des virgules ; les inconnues sont **créées** (`RG-M12-06` en donne le principe pour l'import ; la saisie ne peut pas être plus pauvre) |
| `corps` | non | **Markdown**, converti par `analyserMarkdown()` (`src/lib/contenu/markdown.ts`), la porte unique. Absent ou vide ⇒ document vide valide |

**Aucun autre champ n'est lu.** `typeFiche` et les propriétés typées ne sont **pas** de ce lot :
tu le déclares en écart chiffré, tu ne les combles pas.

## 4. Où le code va

- **`src/lib/rangement/identifiants.ts`** (nouveau) — `identifiantDeNote(titre)` et
  `identifiantSuivant(candidat, essai)`. **Fonctions PURES**, aucune base. C'est la moitié
  éprouvable d'`ARB-062`.
- **`src/lib/donnees/creation.ts`** (nouveau) — `creerUneNote(base, client, demande)`.
- **`src/routes/notes/nouvelle/+page.server.ts`** — l'action `default`, qui remplace le `501`.
- Tests unitaires : `src/lib/rangement/identifiants.test.ts` (obligatoire, **synthétique**, cf.
  `P-26`) et l'extension de `src/lib/donnees/creation.test.ts` pour ce qui s'extrait sans base.

**N'ouvre AUCUN autre fichier.** En particulier : pas `src/vues/`, pas `src/lib/donnees/edition.ts`
(un autre lot y travaille en parallèle), pas `src/routes/notes/[identifiant]/**`.

## 5. L'ordre des portes, et il n'est pas négociable

1. **Le droit d'abord.** `resoudreLaCreationDeNote()` (existe déjà) — refus ⇒ `error(404,
   MESSAGE_INTROUVABLE)`, avant toute lecture du corps soumis. Puis, le domaine et le dossier
   étant connus, **le droit d'écrire SUR CE DOSSIER** — `peutEcrireSurLeDossier()` existe déjà.
   Un rédacteur d'un domaine ne crée pas dans un autre. Même refus, même octet.
2. **La forme ensuite.** Champs manquants ⇒ `fail(400)`. Markdown illisible ⇒ `fail(422)` portant
   les manquements, comme le fait déjà l'action de `/notes/{identifiant}/modifier`.
3. **L'écriture.** Une seule transaction : la ligne `notes`, puis les liaisons d'étiquettes.
4. **L'index après la transaction, jamais dedans** — `entretenirLIndex(base, client, [id])`.
   `ARB-060` : on soumet, on n'attend pas.
5. **`redirect(303, '/notes/' + identifiant)`.** Un POST ne rend pas une page.

## 6. Les pièges de ce lot, nommés

- **`P-28`** — la boucle de collision doit **réessayer sur violation de contrainte**, pas lire
  puis écrire. Éprouve-la : deux notes du même titre, la seconde doit prendre `-2`.
- **`P-26`** — ton test d'identifiant doit rester exercé après ce lot. Il est synthétique par
  construction (fonctions pures) : ne le fonde sur aucun état du dépôt.
- **`P-30`** — la base est PARTAGÉE avec d'autres copies. Ne lance **aucune** batterie qui écrit
  en base (`verif:base`, `test:etancheite`, `mesure:budgets`, `base:semer`). Elles ne sont pas de
  ton critère de sortie.
- **`P-2`** — la copie est déjà synchronisée ; si `vitest` dit « no tests », c'est un échec, pas
  un vide.

## 7. Critère de sortie — et rien d'autre

```
pnpm check        → 0
pnpm test:unit    → 0 échec, et tes nouveaux cas comptés
```

**Tu ne lances pas `verif:maquette`** : tu ne touches à aucun fichier que le banc traverse, et
`ARB-063` §2 explique pourquoi c'est vrai par construction.

Un rapport court : les fichiers écrits, le nombre de cas unitaires ajoutés, les deux codes de
sortie ci-dessus **relevés**, et la liste des écarts déclarés (au minimum : type de fiche et
propriétés typées non pris).
